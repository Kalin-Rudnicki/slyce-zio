Rewriting grammars into LALR(1) / LR(1)

01 The memorable claim

User recollection

“Any LALR(n) can be rewritten into LALR(1).”

StatementVerdict
Every LR(k) language (k≥1) is an LR(1) language (deterministic CFL) True — Knuth 1965
Every LR(k) grammar can be mechanically transformed to an equivalent LR(1) grammar True — Mickunas et al. 1976
The new grammar keeps the same AST / production shape False — need a cover / tree map
LALR-merge conflicts always vanish by “becoming LALR(1)” without change False — may need LR(1), IELR, or a different grammar
Ambiguous grammars become deterministic by rewrite alone False — need policy (prec) or multi-parse
One-liner

Directionally right for LR(k) → LR(1) at the language/grammar level. Not a free pass that preserves your human ADT without an explicit mapping.

02 Grammar-class hierarchy

LR(0)  ⊂  SLR(1)  ⊂  LALR(1)  ⊂  LR(1)  =  LR(k) languages (k≥1)

LALR(1)

Merge LR(1) states that share the same core. Smaller tables; can reintroduce conflicts that pure LR(1) would avoid. Classic yacc/bison default family.

Canonical LR(1)

Full item+lookahead states. Menhir’s world. Handles more grammars; larger automata.

IELR(1)

Start LALR, split states only when merges lose power. LR(1)-class recognition with smaller tables (Bison option).

LR(k), k>1

More lookahead in the grammar sense. Prefer transforming the grammar to LR(1) over shipping a k-lookahead engine.

Important

Languages collapse (LR(k) ≡ LR(1) ≡ DCFL for k≥1). Your written grammar may still not be LR(1) until rewritten.

03 Theory that matters

Knuth (1965)

Invented LR(k). Proved efficient linear-time parsing for the class, and that for every k≥1 a language has an LR(k) grammar iff it is deterministic context-free iff it has an LR(1) grammar.

Mickunas, Lancaster & Schneider (1976)

Give a direct algorithm: arbitrary LR(k) grammar → equivalent LR(1) grammar. Also: prefix-free LR(k) → LR(0); further transforms toward SLR(1) / BRC.

Core moves:

  • Right-stratification — split long RHS for easier surgery
  • Right-context extraction — pull distinguishing right context into structure
  • Premature scanning — force early shift of that context so reduces don’t need k>1
Costs (from the paper)

(1) Original grammatical structure is not preserved. (2) Rule count can grow dramatically (sometimes exponentially in pathological cases).

Decidability

  • Is G LR(k) for fixed k? Decidable
  • Does there exist any k making G LR(k)? Undecidable

Macros must bound k and use heuristics—not search forever.

04 Covers: why rewrite alone is not enough

Language equivalence only guarantees the same strings. Compilers and slyce need the same user-facing values.

Classical name: grammatical cover (Gray & Harrison; used heavily by Mickunas as internal/external parse). ANTLR does the modern UX version: rewrite left recursion, then repair trees so the programmer never sees G′.

slyce today

Hand-cleaned URL grammar + fromCleaned is exactly this architecture. Auto-rewrite should generalize it—not hardcode Url into the macro.

Human rewrites everyone documents

  • Left factoring — factor common prefixes of alternatives
  • Layered expression NTs — encode precedence in grammar shape
  • Nonterminal cloning — manual state split for LALR false conflicts
  • Token merging — lexer absorbs :=, ->
  • Absorb optional trailers — list + trailing sep into one NT

Note: bottom-up LR likes left recursion. Left-recursion elimination is an LL tool, not the primary LALR weapon—except as inspiration for “rewrite + restore trees.”

Non-goals
  • Hardcoding Url / PathAndTrail into core rewrite
  • Silent yacc-style shift preference without annotations
  • Assuming language equivalence ⇒ ADT equivalence

07 Recommended build order

  1. P0 Classify conflicts — LALR-only vs true non-LR(1); better error text.
  2. P1 Stronger automata — LR(1) or IELR-like splitting; NT clone with same ctor cover.
  3. P2 Shape heuristics
    • List + optional trailer absorb
    • Left factor shared prefixes on one NT
    • Delayed commit for competing prefix NTs (host-like)
    • Optional @prec / @left for exprs
  4. P3 Full Mickunas only if heuristics fail; cap grammar size growth.

Success criteria

  • Calculator & JSON stay green with no rewrite
  • URL model derives green via general rewrite + cover
  • Ambiguity without policy still RED
  • No domain-type special cases in FromExtractedType
